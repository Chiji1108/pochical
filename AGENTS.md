# Repository Guide

Pochical is a monorepo: native SwiftUI (`apps/ios`) and Jetpack Compose (`apps/android`) apps, a Cloudflare Workers backend (`apps/server`), the web site, Astro on Workers (`apps/web`), the design documents and the prototype's demo (`apps/design`) and the prototype to keep on a phone (`apps/try`), and the admin site (`apps/admin`). The web apps' shared code sits in `packages/`: the prototype's screens, which the site's top page shows too, and the page around the phones that `apps/design` and `apps/try` show them on (`@pochical/prototype`), the Panda CSS config and the `css()` it writes (`@pochical/styled-system`), and the JSX runtime that breaks Japanese between phrases, with the same breaks for HTML that is not JSX (`@pochical/jsx`).

## Where things live

- Tool versions and tasks are in `mise.toml` (`mise run gen`, `mise run server:test`, `mise run ios:test`, ...).
- Bun's version is in three places, changed together: `mise.toml`, `packageManager` in `package.json`, and the `BUN_VERSION` build variable of each Worker in Workers Builds (`pochical-server`, `pochical-web`, `pochical-design`, `pochical-try`, `pochical-admin`; Settings > Build > Build Variables and Secrets), which reads no version file for Bun.
- Node's version is in `.node-version` alone: mise reads it (`idiomatic_version_file_enable_tools` in `mise.toml`), and so does Workers Builds.
- Generated files are never edited by hand; change their source and regenerate:
  - Wire types: `proto/` → `mise run gen` (into `apps/server/src/gen`, `apps/web/src/gen`, `apps/ios/Packages/PochicalProto/Sources`, `apps/android/proto/src/main`). A change to `Change` or anything it holds fails `mise run sync:check` until the iOS `Sync.schema` is raised and `mise run sync:check -- --write` records it.
  - Numbers every platform shares (limits, the chat's, days', invites', sockets', widgets'), design tokens, mark icons and holidays: `design/` → `mise run gen` (into `spec/design-tokens.json`, `apps/ios/Packages/PochicalDesign/Sources`, `apps/android/design/src/main`). Specs and code refer to them by name, never by value.
  - Icons: the marks' paths from Phosphor via `bun run --cwd design icon:marks`; the iOS app icons and the widgets' `PeekingPoodle` via `bun run --cwd packages/prototype icon:ios`.
  - Workers' types: each Worker's `wrangler.jsonc` and the wrangler in `bun.lock`, with the workerd it pins → `mise run gen:worker-types`, which runs every workspace's `cf-typegen` (into `worker-configuration.d.ts` in `apps/server`, `apps/admin` and `apps/web`). A wrangler bump regenerates them too; CI runs `mise run worker-types:check`. A Worker with a `cf-typegen` and no secrets still declares `"secrets": { "required": [] }`, so its types never come from a computer's `.dev.vars` or `.env`.
  - SQL schemas are Drizzle and their migrations are generated, never written: D1 `apps/server/src/db/schema.ts` (`mise run db:generate -- --name <what>`; better-auth's tables via `mise run auth:schema` first), the Group DO `group-do-schema.ts` (`mise run group-do:generate`), the User DO `user-do-schema.ts` (`mise run user-do:generate`). CI runs `mise run db:check`.
- Behavior shared across platforms is specified in `spec/`. Logic every platform writes again is pinned by `spec/vectors/*.json`, read by `packages/prototype/tests/vectors.test.ts`, `apps/server/test/vectors.test.ts`, `packages/jsx/tests/phrases.test.tsx` (the phrases), PochicalKit's tests and Android's `:kit` tests; a new case goes in the JSON, not in one platform's test. Components are not generated: each platform builds its own, with /design as the reference.
- iOS: `apps/ios/Pochical/Pochical.xcodeproj` (app and widgets, App Group `group.app.pochical`). Hand-written shared code goes in `apps/ios/Packages/PochicalKit` (`mise run ios:test`). `xcodebuild` needs `-skipMacroValidation`. A Debug build in the simulator talks to `mise run server` at `http://localhost:8787`, which needs `apps/server/.dev.vars` (`BETTER_AUTH_SECRET`, any random value, and `BETTER_AUTH_URL=http://localhost:8787`; the `SLACK_*` secrets only to post to Slack from this computer, and wrangler warns while they are absent) and the D1 migrations applied locally (`bunx wrangler d1 migrations apply pochical --local` in `apps/server`).
- Android: the Gradle project is `apps/android` (Kotlin DSL, versions in `gradle/libs.versions.toml`): `:app` (the Compose app, `app.pochical`), `:kit` (what PochicalKit is on iOS, hand-written and below the screens: the clocks, the database and sync, its tests reading `spec/vectors` from the repository), `:design` (the code generated from `design/`) and `:proto` (the code generated from `proto/`, a plain Kotlin library). `mise run android:build` builds the debug APK, `mise run android:release` the minified release bundle (R8's keep rules in `app/proguard-rules.pro`, each one a runtime failure without it) and `mise run android:test` runs the unit tests and lint; both need the Android SDK in `ANDROID_HOME` (Android Studio's, or `local.properties`'s `sdk.dir`) with the `compileSdk` platform, and the JDK from `mise.toml`.
- Admin (spec/admin.md): `apps/admin` is React Router 8 in framework mode, on Workers through the Cloudflare Vite plugin. It reaches the server only through `AdminEntrypoint` (`apps/server/src/admin-entrypoint.ts`), bound as `SERVER`, whose types come from the server's source (`mise run gen:worker-types`); each route's `./+types` come from `react-router typegen`, which `bun install` (prepare) and its `typecheck` run. `mise run admin` serves it in workerd at `http://localhost:3100`.
- Web: `apps/web`'s pages are `.astro` files in `src/pages`, prerendered unless one sets `prerender = false` (the invite page and its images, which ask the server through the `SERVER` binding); React runs only in islands a page marks `client:*` (the top page's phones and skies, `src/components/lp-screens.tsx`). Its middleware breaks the pages' Japanese and gives the on-request pages their headers. `bun run web` serves it at `http://localhost:3000`, beside `mise run server` for the invite page. The repo's `tsc` is TypeScript 7, but `apps/web` declares TypeScript 6 (`@typescript/typescript6` under the name `typescript`) for `astro check`, which needs the TypeScript JS API that 7.0 does not ship ([announcement](https://devblogs.microsoft.com/typescript/announcing-typescript-7-0/)); its `tsconfig.tools.json` is still checked by the root `tsc`. It moves to 7 once TypeScript 7.1 and Astro's `@astrojs/ts-content-mapper` are stable ([withastro/astro#17268](https://github.com/withastro/astro/issues/17268)).
- Design and try: two Workers built from `@pochical/prototype`, with no bindings. `apps/design` is the design documents and the tools beside them at `design.pochical.app`, behind Cloudflare Access: Fumadocs on TanStack Start, its routes in `src/routes` (`src/routeTree.gen.ts` comes from TanStack Start's router plugin). Each document is an MDX file of `content/` (the sidebar's order and groups in its `meta.json`) showing pieces from `src/components`, with Tailwind CSS drawing Fumadocs UI's chrome and Panda CSS the pieces, in the layer order `src/styles.css` sets. The tools under `src/routes/_tool`, /demo and `/_render/share-image` (which `bun run --cwd apps/design image:share` photographs), are full pages outside Fumadocs UI's layout, drawn in the browser alone. `apps/try` is the installable app at `try.pochical.app`, open to everyone and kept out of search until release: a Vite SPA with no router, static assets with no Worker code and every unknown path answered with `index.html`, whose head takes the design tokens and launch images through `head.ts`. Design links to try by the origin in its `.env.development` (try's dev server) and `.env.production` (every build, previews included), read by `src/lib/try-url.ts`; try links to nothing behind Access. Locally, `mise run design` and `mise run try` serve `http://localhost:3200` and `3202`; `mise run design:layout` and `mise run design:demo-layout` measure the documents' and /demo's screens.

## How to build

- Plumbing comes from a maintained library before it is hand-written (check license, activity, fit; name it in the PR). MIT/Apache/BSD/ISC may be added; GPL/AGPL code (Signal, Telegram) is read for ideas only.
- What does the same thing in two places is one piece, not two copies: build on the existing one and make the difference an input. A change to one carries to the others in the same PR.
- Fix the root cause the way the platform or library intends; no timing hacks, sleeps or patches over symptoms. If the conventional answer is to leave a review finding, say so instead of adding special handling.
- The apps are unreleased: change stored shapes directly, with no hand-written data migration, fallback or compatibility code for old saved data. On iOS that means editing a table where it is first created, never adding a migration step: any schema change erases the device's database in every build, TestFlight included, and it syncs again from the server. Likewise a kept session the app cannot read (the Keychain's) is no session: it signs in anew (spec/sync-protocol.md, Signing in). Server SQL schemas still get their generated Drizzle migrations, as above. Android's stored data follows the same rule until release. At release, turn iOS's `erasesOnShapeChange` off, for the database and the kept session alike, and Android's equivalent with it, and append migration steps from then on.
- Update `spec/` (and its vectors) in the same PR as any behavior change; fix spec drift when you see it.
- UI follows the platform first (iOS 26 / Material 3 conventions, system controls and buttons sized by the OS). When /design and a platform differ, judge on the merits and say which side changes. Motion the OS provides is left to the OS.
- TypeScript (`apps/web`, `apps/design`, `apps/try`, `apps/server`, `apps/admin`, `packages/`) is checked by Ultracite: run `bun x ultracite fix`, and avoid `as` assertions other than `as const`. oxlint reads `.astro` files' frontmatter and scripts too, and oxfmt formats `.astro` by Astro's JSX whitespace rules, where a line break between text and a tag renders nothing. Astro's compiler does not apply those rules to text placed directly inside a component, such as `<Link>…</Link>`, and in Japanese a line break left there renders as a space, so a component that takes text trims its slot, as `Link` does.

## How to ship

- main takes pull requests only; name the Linear issue (team POC) in the PR, and file skipped findings or follow-ups there.
- Before merging: run `/code-review` and address it, CI must be green, and review threads resolved. Merge main into the branch first when other PRs landed. Never merge on red.
- The required `ios` status stands for Xcode Cloud (`.github/workflows/ios.yml`): it passes when the PR's own changes leave `apps/ios` and `spec/vectors` alone, or once Xcode Cloud's PR build has passed on the head (or, when it never finished there, on the newest earlier commit of the PR with the same files there), and fails when that build fails. Xcode Cloud's Files and Folders start condition watches the same paths as `.github/scripts/ios-gate.sh`; change both together. When Xcode Cloud never starts on a head that needs it, or is cancelled there, start its build by hand in App Store Connect.
- Once `ios` is a required check in main's ruleset, auto-merge (`gh pr merge --auto --match-head-commit <sha>`) may be used when `/code-review` is addressed and Codex's review of that head is clean; the required checks, `ios` among them, then decide when it merges.
- Deploys happen through Cloudflare Workers Builds on merge; never deploy by hand.
- Android releases happen on merge too: `.github/workflows/android-release.yml` builds the release bundle of each push to main that changes the app, signs it with Play's upload key and puts it on Play's internal testing track, from where it is promoted in Play Console. The upload key and the Play service account live only in the repository's secrets (`ANDROID_UPLOAD_KEYSTORE_BASE64`, `ANDROID_UPLOAD_KEYSTORE_PASSWORD`, `PLAY_SERVICE_ACCOUNT_JSON`) and reach Gradle as `pochicalUpload*` properties; without them the workflow is skipped, and a release build on a computer is signed with the debug key, which Play refuses. versionName is the iOS app's `MARKETING_VERSION`, read from the Xcode project, so a version is raised there once for both apps and reaches Android with its next release; versionCode is the workflow's run number, as Xcode Cloud's build number is iOS's, so the workflow keeps its file name and nothing is uploaded by hand after Play's first upload.
- Renovate (`.github/renovate.json5`) opens the dependency PRs on Monday mornings: patches and minors in one PR (a 0.x package's minor, which may break, in its own), each major in its own, and what must move together in its own group at every update (Bun, vitest, protobuf and Connect, Kotlin and Metro) or at majors (TypeScript, React). They merge like any other PR, after the manual steps their bodies name, such as `mise run gen`.
