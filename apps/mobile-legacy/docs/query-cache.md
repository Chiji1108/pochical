# グループ・チャットの表示キャッシュ

Convexの購読を取得元として維持し、初回応答まで前回の取得結果を表示する。
オフライン送信や送信キューは追加しない。

## 構成

- `account-storage.ts`: カレンダーと表示キャッシュで共通のMMKV保存先作成。
  カレンダーの既存 `work-${userId}` と保存形式、同期処理は維持する。
- `query-cache.ts`: 所有者・形式バージョン・期限・保存量を管理する表示キャッシュ。
- `cached-query.tsx`: 通常クエリーとページ分割クエリーのラッパー。
  Convexの結果がundefinedの間だけキャッシュを使い、空配列・nullも最新結果として扱う。

対象はグループ一覧・未読バッジ・詳細・設定・共有シフト、グループチャットとDM。
チャットは各会話のメッセージ40件・イベント40件まで保存する。
初回取得後はConvexの結果へ置き換え、追加読み込みのカーソル・状態は永続化しない。
仮ID `message:` の送信中メッセージは保存しない。
キャッシュだけを表示している間は既読更新を開始しない。

## 破棄と上限

- 接続先・認証ユーザー・カレンダー所有者の組み合わせにキャッシュを紐づける。
  別の組み合わせで起動すると、以前の表示キャッシュを破棄する。
- 保存インスタンスの識別子を照合し、切り替え前のインスタンスによる書き戻しを拒否する。
- 最新の所属グループ一覧・詳細に基づいて、退会・削除・メンバー離脱に該当する
  グループデータ、DM、共有シフトのキャッシュを破棄する。
- 自分で退会が完了した時点でも、そのグループのキャッシュを破棄する。
- 期限7日、最大100エントリー、データ文字列の概算で合計2MB。
  大きすぎる結果は保存せず、以前の同じキーの値も除去する。
- 保存領域は表示キャッシュ専用。容量制限や破棄がカレンダーの未送信変更に影響しない。

オフライン中は退会・削除などのサーバー側の変更を知ることができないため、
最後に取得した内容が表示される。通信結果が届いた時点で反映する。
最初から保存データがない場合は、既存の読み込み表示を使用する。
匿名から正式アカウントに引き継ぐカレンダーデータは従来どおり保持するが、
表示キャッシュは新しい認証ユーザーに合わせて取り直す。

## 検証

キャッシュ復元、空配列・nullへの置き換え、型の保持、参照の安定性、
アカウント切り替えと旧インスタンスの書き込み拒否、所属変更、期限・容量上限、
保存失敗時のメモリー利用を `tests/query-cache.test.ts` で確認する。
iOS用バンドル生成も確認。端末上での画面遷移・通信切断・再起動の操作確認は別途必要。
