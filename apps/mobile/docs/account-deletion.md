# データ管理とアカウント削除

設定の「データ管理」にはカレンダー削除とアカウント削除を表示する。カレンダー削除は従来どおり同期される削除操作で、アカウント削除の物理消去とは異なる。

アカウント削除はオンラインで受け付ける。匿名アカウントも対象。匿名から連携したアカウントでは、元のワークスペースと連携先の認証情報の両方を削除する。

## 削除範囲

- カレンダーの実データと Replicate の差分・スナップショット等。
- ユーザー情報、ログイン連携、セッション、更新トークン、認証コード、連携用コード。
- グループ参加情報、本人だけのグループ、本人の既読情報・リアクション・在席情報。
- 自分のチャット本文・名前・返信内容。他の投稿内に保存された自分への返信引用も削除表示に置き換える。
- 他のメンバーがいるグループとそのメンバーの本文は維持する。自分の投稿は削除済みの表示だけ残す。通常のグループ脱退ではこの消去を行わない。
- 操作端末のカレンダー MMKV、表示キャッシュ、アカウント対応表、選択グループ、表示設定、ログイン途中情報。消去前に同期書き込みを停止する。

## 処理と再試行

受け付け時にユーザーを削除中にし、他端末の読み書き・新規セッション・アカウント引き継ぎを拒否する。小分けのトランザクションで消去し、進捗を `accountDeletions` に保存する。5分以上進んでいない処理は cron が再開する。完了するとこの一時レコードも削除する。

アプリは受付と完了を区別して表示する。ランダムな受付番号だけを端末に一時保存し、ログアウト後も完了を確認する（プロフィール情報は含まない）。完了の確認後に受付番号も消す。アプリを閉じてもサーバー処理は継続する。

削除中または削除済みのアカウントを検出した別端末も、オンラインで確認できた時点で保存データを消去する。オフラインの別端末や他メンバーの端末に届いた情報を遠隔で即時消去することはできない。表示キャッシュは再取得時に更新される。

## Apple

iOS は削除時に Apple で本人確認し、認可コードをサーバーで交換する。署名・発行者・宛先と登録済み Apple の subject の一致を検証してから revoke を行う。失敗した場合は削除を開始しない。

Web OAuth を使う Android の Apple ログインでは refresh token をサーバー側に保持し、削除時に revoke する。導入前のアカウントには再ログインを案内する。トークンはクライアントの query に返さない。Apple の署名鍵・Team ID・Key ID、および iOS の `AUTH_APPLE_NATIVE_ID` 設定が必要。

## 依存ライブラリ

Replicate と unread-tracking は全データ消去の API がないため、親アプリだけから呼べる bounded purge を Bun patch で追加している。依存更新時には2つの patch と削除テストを確認する。アプリ公開 API から任意のユーザーや collection を指定して呼び出すことはできない。

## 公開前の確認

- Apple 実アカウントでの本人確認・revoke は専用テストアカウントで確認する。自動テストでは実アカウントを削除しない。
- Google Play のストア設定に登録する外部の削除リクエストページは、このネイティブ画面とは別途必要。
- プライバシーポリシーに消去範囲、共有投稿の削除表示、バックアップとログの保持方針を記載する。Convex の運用バックアップ・ログの保持はアプリ DB の削除とは別に管理する。
- 削除ジョブが長時間残る場合は Convex の関数ログと `accountDeletions` を確認する。エラーが持続する場合は修正後 cron が再開する。

検証: `bun test`（複数ページ、引用、共有データ維持、ワークスペース連携、認証情報・同期データ消去、再送拒否、Apple 認証未完了の拒否、保存消去後の遅延書き込み）。
